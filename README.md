# protoc-gen-cmd-handler
`protoc` plugin to generate a command dispatcher targeting embedded systems.

## Motivation
In an embedded C project, there can be a significant amount of boilerplate code required to:
1. Receive commands from a stream e.g., UART
2. Deserialise received commands
3. Dispatch a deserialised command to a handler routine that implements the desired application behaviour.

This demo illustrates a way to autocode such a system by:
- Defining a command schema using `protobuf`
- Autogenerating deserialisation routines using `nanopb`
- Autogenerating a command dispatcher that calls an appropriate handler routine based on the received command type.

## Prerequisites

- `protoc` protobuf compiler.
- Python
- `uv` for managing Python dependencies

## Example Project Usage
0. Run `uv sync` to set up a Python environment containing the project dependencies.
1. Define a command schema in `proto/commands.proto`. This project assumes the schema contains a top level `CommandRequest` message which contains a `oneof` named `command` that enumerates all the possible command messages, thereby providing a way for the generated C code dispatcher to determine which command message type has been received.
2. Run `generate.sh` to run the `protoc` compiler. This script runs the `nanopb` plugin to generate C structs based on the schema, and then runs `protoc-gen-command.py` to generate a command dispatcher and command handler function prototypes based on these `nanopb` structs.


The handler functions declared in the generated `command_handlers.h` need to be implemented by the user. The autogenerated command dispatcher will call these handler functions upon receiving a command.


`src/command_receiver.py` provides an example of how to call the command dispatcher from user code.
